# FINAL PROMPT — LAB KOMPUTER: MODUL 1 DASAR TIK

## 1. PERAN DAN MISI

Bertindaklah sebagai **Senior Full-Stack Web Developer, Software Architect, Security Engineer, dan Perancang Media Pembelajaran Informatika**.

Bangun aplikasi web pembelajaran interaktif bernama **“Lab Komputer: Modul 1 Dasar TIK”** untuk santri putri kelas 1–6 setara SMP–SMA yang masih awam komputer.

Aplikasi harus benar-benar berfungsi, bukan sekadar mockup, prototype visual, atau kumpulan halaman statis. Seluruh tombol, formulir, permainan, kuis, autentikasi, penyimpanan progres, panel guru, ekspor data, dan fitur gamifikasi harus terhubung dengan logika yang sesuai.

Prioritas pengembangan:

1. Keamanan dan integritas data.
2. Kebenaran materi pembelajaran.
3. Fungsi yang lengkap dan dapat diuji.
4. Kemudahan penggunaan oleh pemula.
5. Performa ringan pada laptop spesifikasi rendah.
6. Kemudahan pemeliharaan dan penambahan modul.

Jangan mengklaim suatu fitur sudah berfungsi atau sudah diuji jika belum benar-benar diverifikasi.

## 2. KONTEKS PENGGUNAAN

- Pengguna: sekitar 60 santri, terdiri dari 6 kelas dengan sekitar 10 santri per kelas.
- Setiap santri menggunakan laptop masing-masing.
- Sistem operasi campuran Windows 10 dan Windows 11.
- Resolusi utama 1366 × 768.
- Browser Chrome atau Edge.
- Seluruh perangkat terhubung ke satu jaringan Wi-Fi lokal.
- Laptop guru menggunakan Windows dan sudah memiliki Node.js.
- Laptop guru menjalankan server lokal pada port 8000.
- Santri mengakses aplikasi melalui `http://IP-LAPTOP-GURU:8000`.
- Aplikasi harus tetap berfungsi tanpa koneksi internet.
- Tidak boleh memerlukan akun cloud, CDN, font online, atau aset eksternal.

Seluruh data akun dan progres berada di laptop guru, bukan di masing-masing browser santri.

## 3. ARSITEKTUR DAN BATASAN TEKNOLOGI

Gunakan:

- Backend: Node.js murni dengan modul bawaan.
- Modul server: `http`, `fs`, `path`, `crypto`, `os`, dan `node:sqlite`.
- Database: SQLite dalam file `lab.db`.
- Frontend: satu file `index.html` yang berisi HTML5, CSS, dan Vanilla JavaScript.
- Ilustrasi: SVG inline dan CSS.
- Penyimpanan utama: SQLite di server.
- Penyimpanan sementara offline: `localStorage`, hanya sebagai antrean aktivitas yang belum tersinkronisasi.
- Komunikasi frontend-backend: API HTTP dengan JSON.
- Leaderboard: polling setiap 5 detik, tanpa WebSocket.

Tidak boleh menggunakan React, Vue, Angular, Express, Vite, Bootstrap, Tailwind, jQuery, CDN, atau paket npm.

### Kompatibilitas Node.js

Letakkan komentar berbahasa Indonesia di bagian atas `server.js` yang menjelaskan:

- `node:sqlite` tersedia mulai Node.js 22.5.0.
- API tersebut bersifat eksperimental pada rilis awalnya.
- Versi Node.js yang direkomendasikan adalah versi LTS yang mendukung API SQLite tersebut.
- Jika versi yang terpasang terlalu rendah, perbarui Node.js. Jangan diam-diam mengganti teknologi atau memasang paket tambahan.

Periksa versi Node.js dan dukungan API SQLite saat startup. Jika tidak kompatibel, tampilkan pesan kesalahan yang jelas.

### Struktur proyek

Buat struktur berikut:

- `server.js`
- `index.html`
- `santri.csv`
- `lab.db` — dibuat otomatis.
- `backups/` — untuk backup database.
- `README.txt` — petunjuk instalasi, penggunaan, dan pemulihan data.

File database, backup, CSV sensitif, dan berkas internal server tidak boleh dapat diunduh melalui HTTP publik aplikasi.

Arsitektur materi harus modular. Pisahkan definisi konten, soal, aturan XP, dan konfigurasi dari logika rendering sejauh memungkinkan dalam satu file HTML.

Gunakan struktur seperti:

`const MATERI = {...}`

`const BANK_SOAL = {...}`

`const KONFIGURASI = {...}`

Gunakan fungsi render bersama agar Modul 2, Modul 3, dan seterusnya dapat ditambahkan tanpa menulis ulang seluruh aplikasi.

## 4. SERVER, JARINGAN, DAN DATABASE

### Server lokal

Buat server HTTP yang:

- Mendengarkan pada port 8000.
- Menampilkan alamat IPv4 lokal laptop guru ketika dijalankan.
- Menyajikan `index.html` dan endpoint API yang diperlukan.
- Memeriksa path file agar tidak terjadi path traversal.
- Menetapkan MIME type dengan benar.
- Membatasi ukuran request body.
- Menangani JSON tidak valid dan metode HTTP yang tidak diizinkan.
- Mengirim respons kesalahan yang aman tanpa membocorkan stack trace, PIN, hash, atau token.
- Tidak menyediakan file arbitrer dari direktori proyek.
- Memvalidasi seluruh data dari browser.
- Menggunakan timeout yang wajar untuk request.
- Menutup database dan server secara tertib saat shutdown.

Jelaskan dalam komentar atau README cara menjalankan:

`node server.js`

Sertakan petunjuk Windows Firewall untuk mengizinkan Node.js pada jaringan Private saja jika diperlukan. Ingatkan bahwa AP isolation/client isolation pada router dapat menghalangi koneksi antarlaptop.

Jangan membuka server ke internet atau melakukan port forwarding otomatis.

- Terapkan migrasi skema sederhana agar pembaruan aplikasi tidak merusak database lama.
- Gunakan `busy_timeout` atau mekanisme penanganan database sibuk yang sesuai.
- Pastikan operasi tulis aman ketika banyak perangkat mengirim permintaan bersamaan.

Ketika server dimulai:

- Buat backup database secara konsisten menggunakan mekanisme backup SQLite yang sesuai, termasuk kondisi WAL.

Sediakan petunjuk pemulihan database dalam README. Uji bahwa database hasil backup benar-benar dapat dibuka dan berisi data yang konsisten.

## 5. KEAMANAN DAN AUTENTIKASI

### Akun santri

Guru mengimpor `santri.csv` dengan kolom:

`kelas,nama`

Format contoh:

`kelas,nama`
`1,Aisyah`
`1,Fatimah`
`2,Zahra`

Impor harus mendukung UTF-8, menangani BOM bila ada, memvalidasi kolom, dan menolak baris tidak valid dengan laporan yang jelas.

Jangan menganggap nama santri sebagai identitas unik. Buat ID internal yang stabil dan tangani nama duplikat melalui pemilihan kelas, nama, serta identitas akun yang tidak ambigu.

### Aktivasi PIN

Santri memilih kelas dan nama, kemudian menetapkan PIN empat digit pada aktivasi pertama.

Jangan mengizinkan siapa pun menguasai akun hanya dengan memilih nama santri. Gunakan kode aktivasi awal unik yang dibuat atau dibagikan guru secara aman, atau proses aktivasi yang hanya dapat diselesaikan dengan otorisasi guru.

Setelah aktivasi, santri dapat login menggunakan kelas, identitas akun, dan PIN.

### Hash PIN

- Gunakan `crypto.scryptSync` dengan salt acak per akun.
- Simpan salt dan hash, bukan PIN asli.
- Jangan pernah mencatat PIN ke log.
- Gunakan pembandingan yang aman, seperti `crypto.timingSafeEqual` dengan buffer berukuran sesuai.
- Batasi percobaan login per akun dan sumber koneksi.
- Tambahkan penundaan atau penguncian sementara setelah kegagalan berulang.
- Berikan pesan kesalahan login yang tidak mengungkap apakah PIN atau identitas yang salah.

### Sesi

- Gunakan token acak kriptografis yang memadai.
- Simpan hash token di database; jangan simpan token mentah.
- Token mentah hanya dikirim ke klien melalui mekanisme sesi yang sesuai.
- Gunakan cookie `HttpOnly`, `SameSite=Strict` jika sesuai dengan implementasi HTTP lokal, dan masa berlaku sesi.
- Karena aplikasi memakai HTTP lokal, jelaskan keterbatasan perlindungan cookie tanpa HTTPS dan jangan mengklaim koneksi terenkripsi.
- Cegah akses API tanpa sesi valid.
- Terapkan autentikasi dan otorisasi terpisah untuk guru dan santri.
- Terapkan perlindungan CSRF yang sesuai dengan model autentikasi.
- Logout harus mencabut sesi di server.
- Satu akun hanya boleh memiliki satu sesi aktif. Login pada perangkat baru harus mencabut sesi sebelumnya secara atomik.
- Tombol Logout selalu terlihat.

### Panel guru

PIN guru ditetapkan di konfigurasi `server.js`, tetapi jangan menyimpannya sebagai hash atau PIN yang bisa dibocorkan melalui endpoint konfigurasi. Sediakan konfigurasi awal dan panduan penggantian yang aman.

Gunakan hash dan salt untuk kredensial guru, bukan teks biasa. Terapkan pembatasan percobaan login, sesi guru terpisah, dan pemeriksaan hak akses pada setiap endpoint sensitif.

Jangan mengandalkan penyembunyian tombol atau pemeriksaan JavaScript di browser sebagai pengamanan.

### Mekanisme offline

Jika server tidak terjangkau:

- Simpan antrean aktivitas sementara di `localStorage`.
- Gunakan ID aktivitas unik yang dihasilkan dengan aman.
- Tandai aktivitas sebagai belum tersinkronisasi.
- Jangan menampilkan aktivitas sebagai tersimpan permanen di server.
- Ketika koneksi pulih, kirim antrean secara berurutan.
- Server memvalidasi ulang identitas, aktivitas, status pertemuan, jawaban, dan XP.
- Aktivitas yang sudah diproses tidak boleh memberikan XP lagi.
- Tangani konflik dengan menjadikan database server sebagai sumber kebenaran.
- Berikan indikator status koneksi dan jumlah aktivitas yang belum tersinkronisasi.

Jangan menyimpan PIN, token autentikasi, atau data rahasia dalam antrean offline.

## 7. XP, LEVEL, BADGE, DAN ANTI-CHEAT

Tentukan aturan XP terpusat dalam konfigurasi.

Contoh rancangan:

- Membaca materi: XP diberikan satu kali per aktivitas.
- Menyelesaikan mini-game: XP diberikan satu kali per tingkat atau aktivitas sesuai aturan.
- Menyelesaikan kuis: XP diberikan satu kali untuk penyelesaian yang sah, bukan setiap kali tombol diklik.
- Checklist praktik: XP diberikan satu kali setelah status tugas diterima.
- Level: dihitung dari total XP resmi.
- Badge: diberikan berdasarkan pencapaian yang dapat diverifikasi.

Ketentuan:

- XP maksimal setiap aktivitas ditentukan server.
- Server tidak menerima nominal XP bebas dari browser.
- Aktivitas unik hanya dapat memberi XP satu kali.
- Server memeriksa apakah pertemuan terbuka.
- Skor kuis divalidasi server.
- Skor terbaik disimpan, bukan ditimpa oleh skor yang lebih rendah.
- Percobaan ulang kuis diperbolehkan.
- Gunakan transaksi agar dua request bersamaan tidak memberikan XP ganda.
- Hindari memberikan XP hanya karena membuka ulang halaman.
- Aktivitas membaca materi harus memiliki mekanisme penyelesaian yang jelas, bukan hanya request buatan.
- Jangan menganggap bukti klik checklist sebagai bukti mutlak bahwa tugas di laptop asli telah dilakukan.

Untuk mini-game, lakukan validasi terhadap hasil dan batas aktivitas di server. Jelaskan bahwa permainan pada browser tidak sepenuhnya kebal manipulasi; fokus pada pencegahan manipulasi progres dan XP, bukan klaim anti-cheat sempurna.

## 14. HALAMAN GURU — `/guru`

Buat dashboard guru yang terlindungi autentikasi khusus.

Fitur:

1. Ringkasan jumlah akun santri dan status aktivitas.
2. Impor `santri.csv`.
3. Pratinjau hasil impor dan laporan baris gagal.
4. Filter kelas 1–6.
5. Pencarian nama santri.
6. Progres per santri.
7. Skor kuis dan skor terbaik.
8. Total XP, level, badge, dan checklist.
9. Buka/kunci pertemuan per kelas.
10. Reset PIN dengan mekanisme aktivasi ulang yang aman.
11. Reset progres dengan konfirmasi eksplisit.
12. Ekspor rekap CSV.
13. Tampilan leaderboard besar untuk proyektor.
14. Indikator status server dan database.

Ekspor CSV minimal mencakup:

- ID akun.
- Nama.
- Kelas.
- Skor kuis.
- XP.
- Level.
- Status checklist.
- Status setiap pertemuan.
